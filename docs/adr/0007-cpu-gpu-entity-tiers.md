# ADR-0007: CPU Tier / GPU Tier のエンティティ二層構造

- 状態: 確定
- 日付: 2026-10-05

## 背景

100 万スプライト × 32 バイト = 32MB を毎フレーム CPU→GPU 転送すると、144FPS で約 4.6GB/s となり現実的でない。

## 決定

- **CPU Tier**: 個別ロジックを持つエンティティ (〜10 万)。CPU の ECS が正。GPU には dirty range のみ転送。
- **GPU Tier**: 大量の群 (パーティクル・群衆・流体粒子)。GPU バッファが正。CPU はパラメータとコマンドのみ送る。
- 両者は同じ Unified Sprite Buffer に書き込み、同じ描画パスを通る。

## 理由

- 転送量を「変更分 + コマンド」に抑えられる。
- 描画パスを 1 本に統一でき、カリング・ソートを共有できる。

## 影響

- GPU Tier の要素を個別に CPU から読み書きする API は提供しない (グループ単位のハンドルのみ)。
- GPU→CPU の読み戻しが必要な機能 (例: GPU Tier との当たり判定通知) は非同期・1〜2 フレーム遅延を前提とする。

## 却下した代替案

- 全エンティティを CPU で更新し毎フレーム全転送 → 帯域不足で却下。
