## 3. 実装中に見つけた既存コードの不具合

### 3.1 `ThreadedScheduler` がメイン参加時の例外を捕捉していない

`docs/05` §3.2 手順 3 は「メインスレッドも作業に参加する」と定めており、`runKernel` はメインでも `def.fn(...)` を直接呼んでいた。このときカーネルの例外は `runKernel` をそのまま抜けるとおり、例外の伝播は `PlutoError(InvalidState)` にならず、`errorKernel` が投げた素の `Error` が呼び出し元に届いた。

ブラウザテストで以下を確認した (chunkCount = 13、例外の `constructor.name` は `Error`、`instanceof PlutoError` は false)。

```
"ctor": "Error"
"isPluto": false
```

修正: `runChunkKernel()` を追加し、例外を内部で捕捉して `PlutoError(InvalidState)` に統一した。HOT 規則でループ内の `try` が禁止されているため、失敗は戻り値 (`boolean`) で呼び出し元に伝え、ループを抜けてから `throw` する形にした (`docs/03` §5.2、`.agents/rules/02-performance.md`)。

### 3.2 タスク外のファイル (T-2.4) が作業ツリーに残っていた

`src/transform/` と `tests/unit/transform/` が `PROGRESS.md` 上は `TODO` のまま存在し、`check:boundaries` 7 件、`check:rules` 14 件、`lint` 39 件の違反の原因になっていた。ロードマップの順番を守るという方針をユーザーが承認していたので削除した。T-2.4 は未着手に戻す。
