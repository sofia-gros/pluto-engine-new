## 設計上の判断

### 作らない物は作らない

`docs/06` §1「能力差は隠さない」に従い、以下は例外にする。なんとなくの
エミュレートはしない。

| 機能                                   | 対応                                          |
| -------------------------------------- | --------------------------------------------- |
| 書き込みストレージ                     | `UnsupportedFeature` (レイアウト確定時に検出) |
| compute                                | `UnsupportedFeature` (`validate.ts` が検出)   |
| 間接描画・間接起動                     | `InvalidState`                                |
| 2 描画先で合成が違うパイプライン       | `InvalidArgument` (GL ES 3.0 は全体で 1 種類) |
| スワップチェーンとテクスチャの混ぜ描き | `InvalidArgument`                             |
| テクスチャ配列への描画                 | `InvalidArgument` (層の指定が RHI に無い)     |

### 読み取りストレージはデータテクスチャ

`docs/06` §7 のとおり `RGBA32UI`、幅 2048 texel、1 texel 16 バイト。
書き込みは texel 単位に切り上げ、行をまたぐ範囲は分けて送る。
読み戻しは `UnsupportedFeature` (T-3.4 の受け入れ条件は WebGPU 側だけが
`readBufferAsync` を使うため)。

### 割り当ては宣言順で解決する

`docs/06` §7 の「パイプライン生成時に名前で解決」は、宣言順の列挙で実現した。
uniform ブロックは通し番号で binding を振り、サンプラは通し番号で位置を覚える。
個数が割り当てと合わなければ生成時に `InvalidArgument` にする。
シェーダの著述ミス (Phase 4) を早期に検出するためである。
サンプラの種別 (`sampler2D` / `sampler2DArray` / `usampler2D`) は適用時に
1 個ずつ照合する。

### サンプラはテクスチャと組にする

RHI の `Texture` / `Sampler` エントリは同じユニットを使う。`Sampler` の前に
組になっていないテクスチャ系が無ければ `InvalidArgument` にする。
データテクスチャ化したバッファもユニットを消費する (シェーダ側は
`usampler2D` で読む)。

### 消去は `bufferSubData` の連打で行う

WebGL2 にバッファ消去の API は無い (`clearBufferSubData` は ES 3.0 に無い)。
初期化時に確保した 4KB の 0 埋めブロックで埋める。フレーム中の確保は無い。

### 部分転送の要素数は `instanceof` の列で求める

`writeBuffer` の要素数指定をバイトに直すのに `BYTES_PER_ELEMENT` は使えない
(`DataView` に無いため)。`instanceof` の列で判定する。`as unknown as` は
使っていない。

## 行数制限への対応

1 ファイル 400 行の検査に対し、総量 2960 行を 8 ファイルに収めた。
責務を崩さない範囲で以下を行った。いずれも `docs/02` §12 の責務に収まる。

- 検証に使う固定値は `convert.ts` の変換表に寄せた
  (`RhiCapabilities` の作り出し、固定機能の状態決め、整数書式の判定)。
- テクスチャの生成・転送は `texture.ts`、部分転送は `buffer.ts` に置いた。
- 適用処理は `bind-group.ts` に置いた
  (`docs/02` §12 の「UBO/テクスチャユニット割当」がそのまま該当)。
- 自明な委譲の JSDoc は 1 行にした。内容のある文書は残している。

## テスト (78 件)

GL コンテキストは `Pick` 注釈付きの偽物で代替した。T-3.2 で得た知見
(引数省略の関数は代入では通るが `as` の比較可能性では落ちる) を最初から
適用し、偽物の関数には実型注釈を付けた。`as unknown as` は不使用。
空 interface (`WebGLTexture` など) への `as` は不要なので付けない。

lib.dom のオーバーロード (`bufferData` など) との厳密な照合は
`...args: unknown[]` で受け、必要な引数だけ取り出す形に統一した。
