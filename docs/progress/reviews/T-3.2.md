## 設計上の判断

### ブラウザのグローバル定数を数値で持つ

`GPUBufferUsage.UNIFORM` のような名前空間オブジェクトはブラウザにしか無いので、
Node で読み込むと `ReferenceError` になる。WebGPU 仕様で固定値のため数値で持つ
(D-22 の方針「デバイス依存は `caps` に出す、仕様固定値はコードに書く」に沿う)。

| 定数                | 値の根拠                                           |
| ------------------- | -------------------------------------------------- |
| `GPU_BUFFER_USAGE`  | WebGPU Editor's Draft §5.1.2 (`UNIFORM 0x40` ほか) |
| `GPU_TEXTURE_USAGE` | 同 §6.1.2 (`RENDER_ATTACHMENT 0x10` ほか)          |
| `GPU_COLOR_WRITE`   | 同 (`RED 0x1` ほか)                                |
| `GPU_SHADER_STAGE`  | 同 (`VERTEX 0x1` ほか)                             |
| `MAP_MODE_READ`     | 同 (`READ 0x1`)                                    |

### `buildCapabilities` は convert に置く

`docs/02` §12 は「`webgpu-convert.ts` は変換表」とだけ書いていたが、
`device.features` と `device.limits` から `RhiCapabilities` を作る処理も
変換の一種なのでここに置き、`docs/02` §12 の責務欄を「相互変換表」に改めた。
`device.ts` は 400 行超を避けるためでもある (改訂前 434 行 → 改訂後 389 行)。

### エンコーダのプール (HOT)

`docs/06` §4 の注記に従い、コンストラクタで 2 個の器を作り切る。
`GPURenderPassDescriptor` は深度あり・なしの 2 種を保持し、`begin` では
フィールドへの書き込みだけにする。フレーム中に `new`・リテラル・文字列連結を
使わない。export するメソッドには `@hot` を付けた。

### `writeTimestamp` は実装しない

現行 `@webgpu/types` (0.1.74) に `GPUCommandEncoder.writeTimestamp` は存在しない。
タイムスタンプはパスの記述子 (`GPURenderPassTimestampWrites` ほか) で渡す方式に
変わっている。RHI では任意メソッドなので未定義のままとし、`docs/06` §4 の定義と
`devtools/gpu-timer.ts` (T-10.1) との整合は T-3.4 で判断する。

### その他の仕様差異の吸収

- `setScissor` は WebGPU では `setScissorRect`。RHI の名前は変えず内部で呼ぶ。
- `BindGroupLayoutEntryDesc` に書式が無いので、ストレージテクスチャは
  `rgba32float` に固定 (`docs/08` の GPGPU が `RGBA32F` を使うため)。
- `floatRenderTarget` は `float32-blendable` の有無で判定する。`docs/06` §2 の
  `requiredFeatures` に無いので、`docs/08` の GPGPU は WebGPU 側で要求が必要。
- `ArrayBufferView` (SAB 含む) を WebGPU の転送 API に渡すときは
  `toTransferSource` で絞る。SAB 全体はそのまま渡し、途中範囲は例外にする。

### 偽物の作り方で得た知見

`@webgpu/types` の型は `__brand` で公称型付けされている。`as` での変換は
「対象の必須引数に対応する引数があること」が要る。引数を省略した関数は
代入では通るが `as` の比較可能性では落ちる。偽物の関数メンバーは実型注釈
(`Pick<GPUBuffer, 'mapAsync' | ...>` など) を付けて文脈型付けさせると通る。
`as unknown as` は使っていない。
