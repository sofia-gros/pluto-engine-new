### ミップマップを持たないという判断

`docs/07` のアトラス規格が「KTX2 はミップはレベル 0 のみ使用」なので、`TextureDesc` に `mipLevelCount` を **入れなかった**。サンプラも `FilterMode` 2 種だけで `mipmapFilter` を持たない。これを入れると WebGL2 側で常に無効分岐を持つことになり、実効がないため。

## 設計上の判断

### 頂点バッファ API を持たない

`docs/06` §4 の注記どおり `createVertexBuffer` 系は持たない。四角形は `draw(6, instanceCount)` で `vertex_index` から生成する。

### 頂点シェーダとフラグメントシェーダを `RenderPipelineDesc` に分ける

WebGPU の `GPURenderPipelineDescriptor` は `vertex` と `fragment` の 2 フィールドで別々のモジュールを持つ。RHI も同じ形にした。`ComputePipelineDesc` は 1 本だけ。

### `ShaderSource` を単一オブジェクトにまとめる

WebGPU は `GPUShaderModule` (WGSL のみ)、WebGL2 は `glVertexShader` と `glFragmentShader` の別々。`docs/06` §6 の定義どおり両方を 1 つの型に持たせ、バックエンドが必要とする方を読む。

### `BindGroupEntryDesc` はレイアウトの添字で紐づける

WebGPU の `GPUBindGroupEntry` と同じ方式。`layout` 側の `entries[i]` と `entries[i]` の `type` が一致することを §5.1.1 の検証規則で強制する。

## 検証規則の実装は T-3.2 / T-3.3 の責務

`docs/06` §5.1.1 の 17 個の検証規則は **`create*` を実装するバックエンド側**で行う。T-3.1 はインターフェースと型だけなので、検証コードは置いていない。検証コードを置くファイル名も `docs/02` §12 に無い (`types.ts` は「定数と記述子型」、`device.ts` は「インターフェース」)。

**T-3.2 (WebGPU) と T-3.3 (WebGL2) は §5.1.1 の全規則を両バックエンドで実装すること。** 共通のヘルパ置き場が無いので、必要なら `docs/02` §12 への追記をユーザー指示で 얻ること。
